# atsh-ai — المرجع الموحد الشامل

الحالة: مرجع التنفيذ الموحد — فرع إعادة البناء rebuild/unified-reference.
قاعدة القرار: هذا الملف هو المرجع الأساسي للموقع ولوحة الإدارة. كل تغيير معتمد يحدّث هنا وفي التنفيذ المرتبط به، ولا تُنشأ مواصفات متعارضة في ملفات مستقلة.

## 1. الهدف والنطاق
منصة ثنائية اللغة (العربية RTL والإنجليزية LTR) لعرض خدمات atsh-ai واستقبال طلبات المشاريع وإدارة العملاء وتشغيل الشركة. النطاق: الموقع العام، صفحات الخدمات، نموذج الاستفسار، لوحة الإدارة، إدارة الفريق والصلاحيات، إدارة المحتوى والهوية، المهام، سجل التدقيق، وخدمات الذكاء الاصطناعي المستقبلية.

## 2. خريطة الصفحات
- / الصفحة الرئيسية: القيمة المقترحة، الخدمات، المنتجات، آلية العمل، نبذة، ودعوة لاتخاذ إجراء.
- /services.html فهرس الخدمات.
- /products.html المنتجات والحلول.
- /about.html نبذة وطريقة العمل.
- /contact.html التواصل وطلب المشروع.
- /web-systems.html الأنظمة والمواقع؛ /business-bots.html بوتات الأعمال؛ /cloud-services.html الخدمات السحابية؛ /security-quality.html الأمان والجودة.
- /privacy.html سياسة الخصوصية.
- /admin لوحة الإدارة ومحرر الموقع والهوية والفريق والمهام وسجل النشاط.
- /staff/login و/staff/activate دخول الموظف وتفعيل الدعوة.
- الصفحات المستقبلية: العملاء والطلبات والمشروعات والعروض والفواتير والاشتراكات والاستضافة والنسخ الاحتياطي والدعم ومساعدو AI والتكاملات والتقارير. لا تعتبر مكتملة قبل تنفيذ واجهة وAPI وصلاحيات واختبارات قبول.

## 3. الهوية البصرية ونظام التصميم
لوحة الألوان الابتدائية لإعادة البناء، وليست ادعاءً باستخراج حرفي من مواقع مرجعية:
| الدور | القيمة | الاستخدام |
|---|---|---|
| Background | #0B1020 | الخلفية الرئيسية |
| Surface raised | #121A2B | مساحات ثانوية |
| Surface / Cards | #182338 | البطاقات واللوحات |
| Text | #F4F7FB | النص الرئيسي |
| Muted | #AAB7CA | النص المساعد |
| Primary / Teal | #36C6BD | الإجراء الأساسي |
| Accent / Violet | #A99AFF | إبرازات وذكاء اصطناعي |
| Border | #334155 | الحدود والمدخلات |
| Success | #52C99A | نجاح |
| Warning | #F3BD67 | تنبيه |
| Danger | #F07178 | خطأ وإجراء خطير |

الخطوط: IBM Plex Sans Arabic افتراضيًا؛ خيارات الإدارة Cairo وTajawal وNoto Sans Arabic؛ الإنجليزية Manrope؛ الرموز التقنية DM Mono عند الحاجة. يجب اختبار تشكيل العربية والأوزان والأرقام قبل اعتماد أي خط.

الكروت والمكونات: استدارة معيارية 12px أو 18px أو 24px، حدود واضحة، تباين مقروء، مسافات متسقة، وحالات hover/focus/disabled/loading/error. الأزرار: أساسي وثانوي ونصي وخطير. الحقول لها تسمية ظاهرة وتعليمات ورسالة خطأ محددة. حالات النجاح والتحذير والخطر لا تعتمد على اللون وحده. الواجهة responsive وتدعم RTL/LTR من اتجاه الصفحة.

## 4. تخصيص الهوية من لوحة الإدارة
المحرر يدعم primary وaccent وbackground وsurface وtext وmuted وcard border، واختيار الخط العربي واستدارة البطاقات. القيم تحفظ في إعدادات CMS وتطبق على الصفحات التي تستخدم متغيرات التصميم. يجب التحقق من القيم بقائمة سماح، وإضافة معاينة قبل الحفظ وزر استعادة الافتراضي ورسائل نجاح وفشل واضحة كمتطلبات قبول. لا تقبل CSS أو قيم عشوائية.

## 5. تجربة الموقع
اللغة الافتراضية العربية مع مفتاح لغة واضح. كل صفحة لها عنوان وهدف أساسي. لا تعرض أسعارًا أو نتائج غير موثقة. نموذج الطلب يوضح الحقول المطلوبة وحالة الإرسال، ولا يعلن النجاح إلا بعد تأكيد الجهة المستقبلة. كل واجهة توفر حالات تحميل وفراغ ونجاح وفشل وعدم صلاحية وانتهاء جلسة.

## 6. إدارة أعضاء الفريق والصلاحيات
سير الدعوة: إدخال الاسم والبريد والدور، إرسال رابط/رمز مؤقت، تفعيل العضو لكلمة مروره، ثم إمكانية تعديل الدور أو تعليق الحساب مع تسجيل الفاعل والوقت والسبب. لا ترسل كلمات مرور ثابتة. إزالة العضو لا تمحو سجلاته التاريخية، وتحول المسؤوليات قبل الإزالة.

الأدوار الحالية: Administrator للمالك والإدارة العليا؛ Manager للإدارة التشغيلية المفوضة؛ Staff للمهام والعمليات المسموحة؛ Assistant لوصول محدود؛ Read-only للقراءة فقط. تطبق قاعدة أقل صلاحية، وفحص الصلاحية على الخادم في كل API. لا يستطيع العضو ترقية نفسه. تُحمى الدعوات من إعادة الاستخدام وتحدد صلاحيتها ومعدل المحاولات. يسجل التدقيق دعوات الأعضاء وتعليقهم وتغيير الأدوار وتعديل الهوية والمحتوى والإعدادات، دون كلمات مرور أو أسرار.

## 7. لوحة الإدارة الحالية والمطلوبة
الحالي: محرر الموقع، إنشاء صفحات ومحتوى وبطاقات وصور، ألوان الهوية وخيارات الخط واستدارة الكروت، إدارة الفريق، المهام والإسناد والأولوية والموعد، وسجل النشاط.

المطلوب تحسينه: بحث وفرز وترشيح، معاينة حية، استعادة نسخة سابقة من المحتوى والهوية، تأكيد الإجراءات المدمرة، عدم فقد المدخلات عند فشل الحفظ، ورسائل خطأ مفهومة. وحدات العملاء والمشاريع والفواتير والاستضافة والنسخ الاحتياطي وAI يجب أن تبنى كواجهات وواجهات API منفصلة مع صلاحياتها، لا كعناصر شكلية فقط.

## 8. نموذج البيانات المستهدف
Users, Roles, Permissions, Invitations, Sessions, AuditEvents, Tasks, Pages, ContentBlocks, ThemeSettings, MediaAssets, Leads, Clients, Projects, ProjectMilestones, Quotes, Invoices, Subscriptions, HostingAccounts, BackupRuns, SupportTickets, AIConfigurations, KnowledgeDocuments, Integrations. لكل كيان معرف ثابت وتواريخ إنشاء وتعديل وحالة عند الحاجة. لا تستخدم مخزن JSON لبيانات إنتاجية حساسة أو متعددة النسخ؛ انتقل إلى قاعدة بيانات مُدارة مع نسخ احتياطي واختبار استعادة قبل التوسع.

## 9. البنية التقنية والتشغيل
التطبيق Node.js ويستهدف Azure App Service. التحقق المحلي: npm ci ثم npm run build ثم npm test. تحفظ الأسرار في إعدادات البيئة وGitHub Actions secrets فقط. نجاح /health لا يثبت وحده نجاح المصادقة أو البريد أو النطاق المخصص. لا تشغّل موارد Azure مدفوعة دون مراجعة السعر والاعتمادات والموافقة. لا توسّع عدد النسخ مع مخزن JSON الحالي.

## 10. الأمان والخصوصية
HTTPS، Cookies آمنة HttpOnly/Secure/SameSite، حماية CSRF، تجزئة كلمات المرور، تحديد معدل المحاولات، تحقق من المدخلات على الخادم، فحص نوع وحجم الملفات المرفوعة، منع traversal، وأخطاء لا تكشف الأسرار. حدد الاحتفاظ بالبيانات والحذف وأقل قدر من البيانات الشخصية. اختبر استعادة النسخة الاحتياطية دوريًا، لا مجرد إنشاء النسخة. راجع CSP وHSTS وبقية رؤوس الحماية قبل الإطلاق.

## 11. الذكاء الاصطناعي والتكاملات المستقبلية
بوت الموقع يساعد الزائر على اختيار الخدمة وجمع المتطلبات ولا يخترع أسعارًا أو وعودًا. وفر تصعيدًا بشريًا عند عدم اليقين. افصل بيانات العملاء وصلاحياتهم، ولا تعرض المستندات الخاصة في الاسترجاع العام. قس التكلفة والأخطاء وفق سياسة الخصوصية، ولا تعلن تكاملًا فعالًا قبل اختبار المصادقة والفشل والاسترجاع.

## 12. معايير القبول
- الصفحات والروابط تعمل على الهاتف وسطح المكتب.
- العربية RTL والإنجليزية LTR دون قص أو انقلاب غير مقصود.
- التباين والتنقل بلوحة المفاتيح وحالات التركيز واضحة.
- إعدادات الهوية المحفوظة تنعكس على الصفحات وتستمر بعد إعادة التحميل.
- دعوة الفريق والتفعيل وتسجيل الدخول والصلاحيات وتعليق الحساب والتدقيق مختبرة.
- لا يستطيع غير المخول تعديل محتوى أو مستخدم أو مهمة.
- لا تعلن النماذج نجاحًا دون تأكيد حقيقي.
- build والاختبارات ناجحة، ثم اختبار staging ثم الإنتاج بشكل مستقل.
- كل وحدة مكتملة تعني واجهة وAPI وصلاحية وحالات خطأ واختبارًا، لا مجرد عنصر تنقل.

## 13. مراحل التنفيذ
1. إعادة بناء الواجهة وتوحيد التصميم والاستجابة وRTL/LTR.
2. لوحة الإدارة: محرر المحتوى والهوية والفريق والمهام والتدقيق والمعاينة والإصدارات.
3. ترحيل البيانات إلى قاعدة بيانات مُدارة قبل بيانات الإنتاج أو التوسع.
4. تشغيل الأعمال: العملاء والطلبات والمشروعات والعروض والفواتير والدعم.
5. الاشتراكات والاستضافة والنسخ الاحتياطي والتنبيهات.
6. AI والتكاملات وقاعدة المعرفة وضوابط الوصول وقياس التكلفة.
7. الإطلاق: مراجعة أمنية واختبار استعادة واختبارات قبول ومراقبة وخطة رجوع.

## 14. قرارات تنتظر اعتماد صاحب المشروع
الأسعار والعملات والضرائب وسياسات الدفعات والإلغاء والاسترداد؛ مزود البريد وقاعدة البيانات والتخزين والنسخ الاحتياطي؛ الهوية والخط النهائي؛ صلاحيات كل وظيفة؛ الاحتفاظ بالبيانات ومكان استضافتها؛ مزود AI وحدود التكلفة؛ أسماء النطاقات والبيئات وميزانية الاستضافة. لا تُخمن هذه القرارات ولا تحول القيم المؤقتة إلى سياسة معتمدة.
