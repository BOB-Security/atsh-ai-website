# خطة التنفيذ المرحلية — atsh-ai

> **تحديث تنفيذي — 22 أكتوبر 2026**
>
> - أُضيفت بنية موقع عام متعددة الصفحات تشمل الرئيسية، الخدمات، صفحات تفاصيل الخدمات، المنتجات، من نحن، التواصل، والخصوصية.
> - أُضيف خادم Node.js وملف حزم وأوامر build/test، مع فحوص بنية واختبارات smoke.
> - فحص بناء الملفات والروابط الداخلية عبر GitHub API: اجتازت الملفات فحص الصياغة، ولم تظهر روابط داخلية إلى صفحات مفقودة.
> - **لم يُؤكَّد نجاح CI بعد:** تشغيلات GitHub Actions التي فُحصت بقيت في حالة queued دون runner أو نتيجة نهائية. لا يُعلن البناء ناجحًا قبل نتيجة تشغيل فعلية.
> - تم إيقاف النشر التلقائي من push في مساري Azure، وأصبح النشر الإنتاجي مشروطًا بتشغيل يدوي مع اختيار موافقة صريح. لا توجد نتيجة نشر إنتاجي مؤكدة.
> - نموذج المشروع لا يستقبل الطلبات فعليًا حتى ضبط `INQUIRY_WEBHOOK_URL` إلى خدمة HTTPS موثوقة. لا تُعرض رسالة نجاح عند غياب التكامل.
> - لوحة الإدارة، المصادقة، قاعدة البيانات الدائمة، بوابة العميل والموظفين، التذاكر، البوتات المتصلة، والخدمات السحابية التشغيلية **لم تُنفَّذ بعد**؛ يلزم اختيار مزود الهوية والتخزين والتكاملات قبل تشغيلها بأمان.
> - إشعار الخصوصية والمحتوى القانوني يحتاجان إلى استكمال بيانات الشركة ومراجعة مختص قبل استقبال بيانات حقيقية أو الإطلاق التجاري.

هذه الوثيقة تحول المرجع إلى مهام تنفيذ قابلة للفحص. لا تعني أن المهام اكتملت لمجرد إدراجها.

## المرحلة 0 — قرارات وبنية أساسية
- [ ] تثبيت إطار الواجهة والخادم، وقاعدة البيانات، ومزود المصادقة، والاستضافة.
- [ ] إعداد بيئات التطوير والاختبار والإنتاج وإدارة الأسرار خارج Git.
- [ ] تحديد اللغة الافتراضية ودعم العربية RTL والإنجليزية LTR.
- [ ] إعداد فحوص التنسيق والأنواع والاختبارات والبناء في CI.
- [ ] إضافة سياسة أمان وخصوصية ونسخ احتياطي واستعادة.

## المرحلة 1 — الموقع العام
- [ ] هيكل متجاوب مع تنقل واضح.
- [ ] الرئيسية والخدمات والمنتجات والأعمال ومن نحن والتواصل.
- [ ] حالة حقيقية لكل منتج، وعدم عرض بيانات عملاء أو نتائج غير موثقة.
- [ ] نموذج تواصل مع تحقق خادمي وحالات نجاح وفشل واضحة.
- [ ] بيانات SEO الأساسية وسياسة الخصوصية المناسبة.

- [ ] إدارة محتوى الصفحات والخدمات والمنتجات والمشروعات.
- [ ] إدارة طلبات التواصل وسجل التدقيق.
- [ ] مسودات ومعاينة ونشر وأرشفة.

من نتيجتها.

- [ ] فصل صلاحيات المبيعات والمالية واعتماد التسويات.

## قرارات نطاق وأولوية معتمدة
- [ ] تثبيت اسم العلامة atsh-ai في الواجهة والمحتوى.
- [ ] تأكيد اسم النطاق الصحيح قبل إعداد DNS؛ الصيغة المكتوبة `www.atsh.-ai.com` تبدو غير صالحة، ولا يُفترض أنها `www.atsh-ai.com` دون تأكيد.
- [ ] صياغة الخدمات حول قدرات الذكاء الاصطناعي والتعاون والتنفيذ بواقعية، دون وعود غير مختبرة.
- [ ] تنفيذ نموذج «تذكرة إحالة فرصة» من الموقع برقم مرجعي.
- [ ] لوحة الإدارة لمراجعة الإحالات والتواصل مع مقدمها وتحديث الحالة.
- [ ] لا يُعتمد إسناد أو عمولة إلا بموافقة رسمية موثقة وتكليف يحدد التفاصيل.
- [ ] حفظ قرار الإدارة والتكليف وتاريخ الاعتماد والتعديلات في سجل تدقيق.
- [ ] إعطاء إدارة الموقع والأقسام وتذاكر الفرص الأولوية قبل أنظمة الموظفين المتقدمة.

## خدمة العملاء: بوت ودردشة ومرفقات وتذاكر
- [ ] إعداد ساعات العمل والمنطقة الزمنية من لوحة الإدارة.
- [ ] دردشة نصية تميز بوضوح بين البوت والموظف البشري.
- [ ] استقبال وإرسال المرفقات مع حدود أنواع وأحجام وحماية وصول.
- [ ] تحويل المحادثة إلى تذكرة ذات رقم مرجعي وحالة واضحة.
- [ ] توجيه التذاكر حسب النوع: استفسار، مشروع، دعم فني، إحالة شريك.
- [ ] قاعدة معرفة معتمدة يجيب منها البوت، مع تصعيد الأسئلة غير المؤكدة.
- [ ] خارج ساعات العمل يوضح عدم توفر الدعم البشري ويتيح إرسال تذكرة.
- [ ] لا يقرر البوت أسعارًا نهائية أو عقودًا أو موافقات إحالة أو عمولات.
- [ ] مراجعة خصوصية مزود الذكاء الاصطناعي وفحص المرفقات قبل الإطلاق.
