# خطة تأسيس التسويق بالذكاء الاصطناعي لشركة atsh-ai

**الحالة:** خطة تنفيذية أولية — لا تعني أن الموقع أو أي تكامل تسويقي قد نُفذ.
**النطاق:** تسويق atsh-ai نفسها وبناء العلامة وجذب العملاء. ليست منتجًا تسويقيًا للعملاء.
**الارتباط:** مرجع الموقع `docs/ATSH_AI_WEBSITE_EXECUTION_REFERENCE.md` وقائمة التنفيذ `docs/IMPLEMENTATION_BACKLOG.md`.

## 1. الهدف والنهج

نبني الموقع والمنظومة بالتوازي مع تأسيس التسويق. لا نفترض أن الموقع منشور أو جاهز لاستقبال العملاء؛ يجب اختبار كل صفحة ونموذج واتصال قبل توجيه الإعلانات إليه.

يبدأ مدير التسويق AI كنظام مساعد داخلي يستخدم نموذجًا جاهزًا وقاعدة معرفة معتمدة. يجهز الخطط والمسودات والتحليلات، ويترك النشر والإنفاق والإجابات التجارية الحساسة للموافقة البشرية. لا نبني نموذجًا من الصفر في هذه المرحلة.

الأهداف:
- تأسيس هوية ورسالة متسقة لـ atsh-ai.
- بناء حضور عضوي مستمر ومفيد.
- تحويل الاهتمام إلى استفسارات قابلة للمتابعة.
- اختبار إعلانات صغيرة فقط بعد اجتياز الموقع اختبارات الجاهزية.
- اتخاذ قرارات لاحقة بناءً على بيانات فعلية، لا أرقام افتراضية.

## 2. ضوابط لا بد منها

- تُعرض الخدمات بوصفها خدمات مقترحة فقط إلى أن تتأكد القدرة على تنفيذها؛ لا ادعاءات غير موثقة عن عملاء أو نتائج أو منتجات مكتملة.
- تُراجع حالة كل منتج ومشروع قبل نشره، مع التمييز بين قيد التطوير والتجريبي والمتاح.
- لا تُنشر بيانات العملاء أو بيانات شخصية في نموذج AI دون أساس وصلاحيات ومراجعة خصوصية.
- لا تُرسل رسائل جماعية ولا تُنشر منشورات ولا تُشغّل إعلانات آليًا دون موافقة صريحة.
- لا يحدد النموذج سعرًا نهائيًا أو موعد تسليم ملزمًا أو يقبل عقدًا أو يقدم ضمانات نيابة عن الشركة.
- لا تُحفظ مفاتيح API أو كلمات المرور في Git. تُراجع تكلفة أي مزود قبل تفعيله.
- لا يُعلن عن اكتمال مهمة إلا بعد تنفيذها واختبارها وتوثيق النتيجة.

## 3. مسار التنفيذ المرحلي

### المرحلة A — تأسيس الرسالة وقاعدة المعرفة
**الاعتماد:** مرجع الشركة والهوية والخدمات في وثيقة التنفيذ التأسيسية.

- [ ] اعتماد وصف مختصر للشركة ورسالتها الأساسية بالعربية.
- [ ] إعداد نسخة إنجليزية متسقة بعد تثبيت الرسالة العربية.
- [ ] تحديد شريحة أولية من العملاء ومشكلاتهم؛ لا نستهدف الجميع برسالة واحدة.
- [ ] تصنيف الخدمات إلى: جاهزة للعرض، قيد التحقق، مؤجلة.
- [ ] إعداد ملف معرفة يتضمن الحقائق المعتمدة والأسئلة المتكررة والادعاءات الممنوعة.
- [ ] اعتماد نبرة الكتابة والقواعد البصرية ودعوة موحدة للتواصل.

**مخرج القبول:** مرجع واحد معتمد يستطيع مدير التسويق الرجوع إليه دون اختلاق معلومات.

### المرحلة B — تجهيز الموقع لاستقبال التسويق
**الارتباط المباشر:** المرحلة 1 (الموقع العام)، نموذج التواصل، SEO، وإدارة المحتوى في `IMPLEMENTATION_BACKLOG.md`.

- [ ] تنفيذ صفحة رئيسية تعرّف الشركة وتوجّه الزائر إلى خدمة أو طلب مشروع.
- [ ] نشر صفحات الخدمات التي تتوفر لها معلومات دقيقة فقط.
- [ ] إظهار حالة المنتجات والمشروعات الداخلية بصدق؛ لا عناصر أو شهادات وهمية.
- [ ] تنفيذ نموذج تواصل يتحقق من المدخلات ويعرض نجاحًا أو فشلًا حقيقيًا.
- [ ] التأكد من وصول الاستفسار إلى قناة متابعة فعلية وتسجيل رقم مرجعي عند اعتماده.
- [ ] إضافة عناوين ووصف SEO ومعاينات المشاركة وروابط واضحة.
- [ ] اختبار الهاتف وRTL/LTR والروابط والنماذج والأداء والخصوصية.
- [ ] التحقق من النطاق والاستضافة وHTTPS قبل إعلان الجاهزية.

**بوابة القبول:** لا إعلانات مدفوعة قبل التأكد عمليًا من أن العميل يستطيع إرسال استفسار وأن الفريق يستطيع استلامه ومتابعته.

### المرحلة C — تشغيل التسويق العضوي
- [ ] اختيار قنوات البداية وفق الجمهور والقدرة على الاستمرار، ثم توثيق سبب الاختيار.
- [ ] إنشاء تقويم محتوى لأربعة أسابيع.
- [ ] تجهيز محتوى يشرح مشكلات تقنية وحلولًا ومناهج عمل، مع تعريف صريح بـ atsh-ai.
- [ ] إعداد منشورات تعريفية بالخدمات التي تم التحقق من جاهزيتها.
- [ ] ربط كل منشور بهدف واضح: الوعي، الثقة، زيارة صفحة خدمة، أو استفسار.
- [ ] مراجعة المحتوى بشريًا قبل النشر وتسجيل رابط المنشور ونتيجته.

**مخرج القبول:** جدول نشر قابل للاستمرار ومحتوى أصلي موثوق؛ لا يشترط النشر الآلي.

### المرحلة D — مدير التسويق بالذكاء الاصطناعي
**النطاق الأولي منخفض التعقيد:** نموذج جاهز + تعليمات + قاعدة معرفة + مراجعة بشرية.

- [ ] إنشاء تعليمات دور مدير التسويق وحدود صلاحياته.
- [ ] تمكينه من اقتراح خطة أسبوعية وأفكار محتوى ومسودات متعددة الصيغ.
- [ ] إلزامه بتمييز الحقائق المعتمدة عن الافتراضات والأسئلة التي تحتاج مراجعة.
- [ ] إنشاء قائمة مراجعة قبل النشر: الدقة، ادعاءات الخدمة، الخصوصية، اللغة، الدعوة للإجراء.
- [ ] إنشاء قالب تقرير أسبوعي من البيانات المتاحة.
- [ ] تقييم جودة المخرجات وتكلفة النموذج قبل أي تكامل برمجي.
- [ ] لا يُربط بموقع أو حساب اجتماعي أو منصة إعلانات قبل تحديد المزود والصلاحيات والخصوصية والتكلفة.

**مخرج القبول:** سير عمل موثق يمكن تكراره يدويًا بأمان قبل أتمتة أي إجراء خارجي.

### المرحلة E — قياس التحويل ثم اختبار الإعلان
- [ ] تعريف الاستفسار الجاد والفرصة التجارية ومصدر الإحالة.
- [ ] تسجيل الزيارات والاستفسارات ومصدرها باستخدام أدوات مناسبة للخصوصية.
- [ ] إعداد تقرير أسبوعي: الزيارات، الاستفسارات، الفرص، الإنفاق، وتكلفة الاستفسار عند توفر البيانات.
- [ ] اختيار خدمة واحدة وصفحة هبوط واحدة ورسالة واحدة للاختبار الأول.
- [ ] تحديد سقف إنفاق شهري وموافقة مسبقة قبل تشغيل الحملة.
- [ ] إيقاف الحملة إذا لم تنتج بيانات مفيدة أو تجاوزت سقف الإنفاق.
- [ ] عدم زيادة الإنفاق إلا بعد مراجعة جودة الاستفسارات والقدرة على تحويلها إلى عملاء.

## 4. ترتيب التنفيذ المقترح لأول 30 يومًا

الأيام 1–7: تثبيت رسالة الشركة وقاعدة المعرفة وتحديد الجمهور الأولي.
الأيام 8–14: معالجة متطلبات الموقع التي تمنع استقبال الاستفسارات، وفق حالة التطوير الفعلية.
الأيام 15–21: تشغيل إنتاج المحتوى بمساعدة AI ومراجعته ونشره يدويًا.
الأيام 22–30: مراجعة البيانات؛ يبدأ اختبار الإعلان فقط إذا اجتازت صفحة الهبوط ونموذج التواصل بوابة القبول.

هذا جدول مبدئي يعتمد على حالة التطوير الفعلية والموارد المتاحة، وليس وعدًا بأن الموقع أو التكامل سيكتمل في هذه المواعيد.

## 5. مؤشرات الأداء

تُسجل قيمة خط الأساس أولًا ولا تُختلق أهداف رقمية قبل توفر البيانات:
- انتظام نشر المحتوى وجودته.
- زيارات صفحات الخدمات ومصادر الزيارات.
- عدد الاستفسارات المستلمة فعلًا.
- نسبة الاستفسارات الجادة إلى إجمالي الاستفسارات.
- عدد الفرص التي انتقلت إلى محادثة أو عرض مشروع.
- الإنفاق وتكلفة الاستفسار الجاد عند تشغيل الإعلانات.
- الوقت الذي وفره سير عمل AI، مع مراقبة الأخطاء والمحتوى المرفوض.

## 6. الربط بقائمة التنفيذ الرئيسية

تُربط المهام البرمجية اللازمة بهذه الخطة في `docs/IMPLEMENTATION_BACKLOG.md` بدل إنشاء نظام موازٍ متضارب. الأولوية العملية:
1. الموقع العام والمحتوى الصادق.
2. نموذج التواصل ووصول الطلبات إلى قناة متابعة فعلية.
3. إدارة طلبات التواصل ومصدر الاستفسار.
4. إدارة المحتوى والصلاحيات.
5. قياس التحويلات بعد مراجعة الخصوصية.
6. تكاملات AI والتسويق الخارجي بعد اختبار سير العمل الداخلي.
